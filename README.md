# LarkPM 需求工作台

Windows 桌面应用 1.0，完整窗口＋托盘。以可配置的飞书需求表为数据源，提供模块需求看板、平铺个人工作台、版本甘特；依赖、个人分支和版本目标保存在本机。当前版本变化见 [CHANGELOG.md](CHANGELOG.md)。

## 运行

下载安装包 `LarkPM_1.0.0_x64-setup.exe`，或完整解压 `LarkPM-1.0.0-windows-x64.zip`，运行 `LarkPM.exe`。便携包须保留同目录 `sidecar/larkpm-backend.exe`，系统需要 Microsoft Edge WebView2 Runtime。关闭窗口会隐藏至托盘；托盘菜单可重新显示或退出。

首次可点击“载入流程示例”，创建独立的虚构项目，验证功能开发、UI、切摆并行，动效与接入串接。示例不连接真实飞书，也不会替换其他项目。

## 配置多个项目

“设置”包含使用者、人员与部门、项目与连接三个分区。使用者可保存名称并选择关联人员，关联后“我的任务”按稳定人员 ID 筛选。人员目录汇总各项目已读取的处理人，同名人员不会合并；也可手动补充。

人员默认部门在本机跨项目共用。需求详情选择处理人后自动带出并去重；未配置部门会提示待补充。取消“使用人员默认部门”可为当前需求手动指定部门（从下拉列表逐个添加，可移除），手动值不随默认值更新；重新勾选可恢复自动。设置和需求部门只保存在本机，不回写飞书。旧任务不需迁移即可使用默认部门。

### 本地人员状态与部门

人员状态在本机手动维护，支持在职、已离职、暂不使用和待确认。新读入人员默认待确认；重新读取飞书只补充人员，不覆盖已保存的状态与部门。默认隐藏离职／暂不使用，可通过状态筛选查看全部并恢复使用；历史任务始终保留原处理人，新分配下拉不推荐隐藏人员。

可勾选多人，批量应用状态或统一部门，再点击“保存设置”。部门从当前项目需求表的选项中选择，颜色采用近似飞书的标签配色；同一人员配置一次后跨项目复用；新增需求选择该人员后自动带出部门，单条需求仍可手动覆盖。未配置部门不会猜测填充。进入人员与部门时会读取尚未缓存的选项，也可点击“更新部门选项”；读取飞书需求时同步更新。部门字段默认名为“部门”，可在项目字段映射中修改。旧值不在当前表选项中时保留并标记，不会自动清空。

通讯录授权入口、同步接口及自动调用已关闭；程序会清理旧配置中的通讯录授权请求范围，保留需求表所需授权。原有飞书需求表读取、手动回写仍按项目连接使用，不需要申请通讯录权限。

1. 在“项目与连接”中新建连接，填写项目名称和需求表链接（`/base/...?...table=tbl...`），也可直接填写 Base Token、Table ID。
2. 将标题、起止时间、处理人、开发状态、父记录、版本等字段映射为实际字段名或字段 ID；状态选项也可按表配置。
3. 每个项目分别保留任务、依赖、版本目标和回写清单。已有任务的连接不能换绑另一张表，换表请新建连接。
4. 字段名/ID可自行配置，当前日期字段按日期处理（UTC+08:00），不保留小时分钟。处理人回写需要真实飞书 open_id；可以从项目已有人员选择。

当前每个项目连接一张需求表，多个项目共用本机配置的同一飞书应用和登录身份。尚不支持每项目不同账号、删除项目、Wiki 链接自动解析或把本地任务创建成飞书记录。

## 飞书授权

使用你自己的飞书自建应用；产品不读取或复制开发工具 lark-cli 的登录凭证。

1. 在飞书开发者后台配置 OAuth 重定向地址：`http://127.0.0.1:18765/callback`。若端口冲突，可在桌面设置改端口，同时修改后台地址。
2. 开通应用所需的多维表格读取/更新权限及用户授权，保证应用可用范围和当前用户都能访问目标表；默认请求范围为 `bitable:app offline_access`。应用权限变更需按企业流程发布后生效。
3. 先保存项目连接，再在“飞书账号授权”保存 App ID、App Secret，点击生成授权链接，再主动打开授权页面。
4. 浏览器授权完成后返回 LarkPM，状态自动更新。授权链接五分钟内有效，回调校验 state 和 PKCE。
5. 点击“读取飞书”。需求父子关系仅用于模块归类，不会自动变成串行依赖。

App Secret、access token、refresh token 用 Windows DPAPI 加密，保存在当前 Windows 用户的数据目录；不进入项目仓库。该设计面向本人使用的本地 Demo，不是面向多人分发的应用密钥架构。

参考：[飞书授权码与 PKCE](https://open.feishu.cn/document/authentication-management/access-token/obtain-oauth-code)、[用户凭证](https://open.feishu.cn/document/authentication-management/access-token/get-user-access-token)、[读取记录](https://open.feishu.cn/document/server-docs/docs/bitable-v1/app-table-record/list)、[更新记录](https://open.feishu.cn/document/server-docs/docs/bitable-v1/app-table-record/update)。

## 任务和依赖

- 个人任务平铺，可按处理人、版本、模块关键词筛选。上游已完成项目可折叠。
- 状态“交付就绪”对应完成；下游的就绪提示随前置条件计算，实际开工仍需手动改为进行中。
- 取消完成回到进行中，下游重新显示阻塞。已开工下游保留实际状态，同时显示撤回后的阻塞原因，不擅自回滚工作。
- 在节点新增分支任务，默认以该节点为上游，可编辑前置关系；分支默认本地，不创建飞书记录。
- 依赖编辑拒绝循环和跨项目关联。
- 切摆节点可标记“原型图与流程图已可用”，规则候选据此允许切摆与功能开发/UI 并行。
- 甘特使用真实起止日期，展示依赖线和版本目标；缺日期单列待排期，不推测工期。版本目标由你设置，不把最后一个任务的截止日期冒充目标日期。

**自动识别的当前边界：** 本版按同模块、同版本、任务标题与常见交付规则生成候选依赖，逐条人工确认。它能覆盖提供的新系统样例和原型图条件，不能保证识别任意需求正文中的语义、附件里的交付标准或复杂跨模块关系。未向外部 AI 发送需求数据，也没有将此规则系统包装为完整 AI 语义识别。

## LinkinNotes 双向联动

需使用本次配套构建的 LinkinNotes，旧版没有“需求待办”入口。

1. 在 LarkPM 的任务详情点击“转为 LinkinNotes 个人待办”，整条转一条，重复点击不会重复创建。
2. 在新版 LinkinNotes 顶部点击“需求待办”。这些任务使用独立的需求待办区域，与原有好用便签四象限分开，不改写好用便签私有数据库来塞入新字段。
3. 两个应用在同一 Windows 用户下共用本地任务库，标题、起止时间、处理人和完成状态直接联动；另一端轮询约 2.5～4 秒更新。
4. LinkinNotes 勾选完成即交付就绪，无个人验收环节；取消完成改为进行中。支持从节点新增本地后续分支。
5. 个人笔记只由 LinkinNotes 读写，不包含在 LarkPM 快照或飞书回写中。
6. 乐观锁发现两边同时修改时保留输入，显示最新内容，由你选择采用最新或保留输入重存。

联动仅限同机，不是跨设备同步。原有私人待办不会被扫描、导入或回写到飞书需求表。

## 手动回写与冲突

“同步与回写”展示飞书基线和本地修改，逐字段勾选标题、起止时间、处理人、完成状态后提交。依赖、版本目标、个人笔记和本地分支不回写；本版不写验收状态。

提交前重新读取远端：同一字段双方都有不同修改时，先由你选择本地或飞书内容。记录不再可见时保留本地副本，阻止回写。请求中途失败会保留未确认修改，并提示先重新读取，避免把未知结果当成功。

飞书 API 未提供本实现可用的原子条件更新，提交前检查与实际写入之间仍有很小的竞争窗口；多人同时修改同一记录时应重新核对远端。

## 本地数据与备份

默认位置：`%LOCALAPPDATA%\LarkPM\`。`workspace.db` 保存项目、任务与依赖，`auth/` 保存公开连接配置和加密凭证。LinkinNotes 个人笔记在同一库的独立表，LarkPM 接口不会读取该表。

备份时先从托盘退出两个应用，再复制整个目录。跨 Windows 用户迁移需重新授权，DPAPI 凭证不能直接换用户使用。开发验证可用 `LARKPM_DATA_DIR` 指定隔离目录。

## 开发和检查

```powershell
npm install
python -m unittest discover -s tests -v
npm run build
python scripts/make-icon.py
./scripts/build.ps1
```

开发运行：先从托盘退出发布版，再执行 `npm run tauri:dev`，命令会自动启动 Vite 和“开发验收窗口”。界面修改保存后热更新；开发后端直接运行 Python 源码，修改后端后退出开发进程再重新运行此命令。开发版默认沿用同一 Windows 用户的项目、授权和任务数据；使用隔离数据时先设置 `LARKPM_DATA_DIR`。构建需 Node、Rust/MSVC、Python 与 PyInstaller。更新共享 Workspace 后执行 `./scripts/sync-linkin.ps1`，再分别重建两个应用。

`scripts/headless-server.py` 仅用于隔离 UI 检查：临时数据库、禁止外部操作，退出后清理。它不是产品运行方式。

真实账号授权、真实飞书回写、托盘交互和当前机器上的窗口视觉效果，需用户运行成品后验收；自动检查不替代这些结果。
